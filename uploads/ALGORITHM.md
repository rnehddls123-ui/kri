# ALGORITHM.md — 동선 알고리즘 설계

> 동선 에이전트가 이 문서를 기준으로 구현됩니다.
> 임의 수정 금지. 수정 시 영향 단계 명시 필수.

## 노드 데이터 구조

> 노드는 사전 구축하지 않음. Google Places 검색으로 실시간 자동 수집.
> 데이터 에이전트가 "[권역] [카테고리]" 쿼리로 후보 장소를 가져옴.

### 노드 구조 (Google Places 수집 후 가공)

```json
{
  "place_id": "ChIJ...",
  "장소명": "Google Places 결과",
  "권역": "나카메구로",
  "카테고리": "카페·디저트",
  "좌표": { "lat": 35.6439, "lng": 139.6990 },
  "평점": 4.5,
  "영업시간": { "open": "08:00", "close": "23:00" },
  "예산레벨": "Google price_level → 절약/보통/프리미엄 매핑",
  "평균체류시간": "카테고리 기반 기본값 적용"
}
```

### 가공 규칙

```
예산레벨 매핑:
Google price_level 0~1 → 절약
Google price_level 2   → 보통
Google price_level 3~4 → 프리미엄

평균체류시간 (카테고리 기본값):
음식·맛집 1.0h / 카페 1.0h / 시장 1.5h / 쇼핑 2.0h
예술·전시 1.5h / 자연·공원 1.5h / 체험 2.0h / 근교 종일
```

### 검색 품질 관리 (리스크 완화)

```
- 평점 4.0 이상 + 리뷰 수 일정 이상만 후보 채택
- 관광지 편중 방지: touristDensity 고려해 일부 로컬 우선
- 영업시간 없는 곳 제외
```

## 하루 동선 구조

> 모든 일자는 아래 물리적 흐름을 기준으로 구성된다.
> 입국일/출국일은 공항 이동이 포함되며, 중간 일자는 숙소 출발/복귀로 시작·종료.

```
[입국일]
공항 도착
↓ 이동 (공항→숙소, 수단+소요시간)
숙소 체크인 (1시간 고정)
↓ 이동 (숙소→권역, 수단+소요시간)
권역 A
  └ 노드1 (장소명 / 카테고리 / 체류시간)
  └ 이동 (도보 or 대중교통 + 소요시간)
  └ 노드2
  └ ...
↓ 이동 (권역→숙소, 수단+소요시간)
숙소 복귀

[중간 일자]
숙소 출발
↓ 이동 (숙소→권역)
권역 A
  └ 노드1 → 노드2 → ... → 노드N
↓ 이동 (권역A→권역B) ← crossZone 발생 시
권역 B
  └ 노드N+1 → ...
↓ 이동 (마지막 권역→숙소)
숙소 복귀

[출국일]
숙소 체크아웃 (1시간 고정)
↓ 이동 (숙소→권역) ← 활동 가능 시간 있을 경우만
권역 A (단축 일정)
↓ 이동 (권역→공항, 수단+소요시간)
공항 도착 (출발 2시간 전 도착 고정)

[숙소 변경일] (숙소 2곳 이상일 때)
이전 숙소 체크아웃 (1시간 고정)
↓ 이동 (이전 숙소→권역, 짐 보관 or 휴대)
권역 활동 (노드 1개 감산)
↓ 이동 (권역→신규 숙소)
신규 숙소 체크인 (1시간 고정)
↓ 이동 (신규 숙소→권역)
신규 숙소 권역 활동
↓ 이동 (권역→신규 숙소)
숙소 복귀
```

## 9단계 알고리즘

### 1단계 — 전처리

```
[시간]
페이스 질문 내 기상패턴 흡수:
- 페이스 선택 + "일찍 시작" → 아침형 (08:00~09:00)
- 페이스 선택 + "느긋하게"  → 올빼미형 (11:00~12:00)

박수 자동 계산:
- 출국 항공편 날짜 - 입국 항공편 날짜 = 박수 (별도 입력 없음)

[예산]
절약(~6천엔/일)    → 예산레벨 "절약" 장소만 필터
보통(6천~1.5만엔)  → "절약"+"보통" 장소 허용
프리미엄(1.5만엔~) → 모든 예산레벨 허용
(기준: 1인 1일 활동비 = 식사+카페+입장료, 숙소·항공 제외)

[카테고리 — 메인/서브 분리]
카테고리_메인: 필수 1개 → 캐릭터 네이밍 + 동선 노드 배분에 반영
카테고리_서브: 필수 1개 → 동선 노드 배분에만 반영
※ 메인과 서브는 반드시 다른 카테고리여야 함

[사진]
인생샷 필수  → photogenic 추정값 가중치 +30%
관심없음     → photogenic 가중치 제거
※ photogenic 수치: Google Places 평점+리뷰수+카테고리 조합으로 추정

[동행]
가족(아이있음) → nightlife 장소 제외
```

### 2단계 — 활동 가능 시간 계산

```
입국일: 도착시간 + 공항이동시간 + 숙소체크인(1시간) = 실제 활동 시작시간
출국일: 출발시간 - 공항도착여유(2시간) - 공항이동시간 - 체크아웃(1시간) = 실제 활동 종료시간

공항 이동시간 (공항→도심 숙소 기준):
NRT T1/T2 → 60~80분
NRT T3    → 55~75분
HND T3    → 30~40분

숙소→권역 이동시간:
숙소 권역 기준 Google Maps Distance Matrix API로 실측
없을 경우 도심 평균 20분으로 대체
```

### 3단계 — 일자별 노드 개수 결정

```
페이스 × 체력 조합표:

           체력높음  체력보통  체력낮음
빡빡(4~5)    5        4        3
보통(2~3)    3        3        2
여유(1~2)    2        2        1

입국일·출국일은 활동 가능 시간에 따라 위 수치에서 자동 감산
```

### 4단계 — 권역 할당

```
숙소 권역 기준 가까운 순서로 일자별 순환 할당
같은 권역 연속 2일 이상 금지 (근교 제외)
근교(가마쿠라/하코네 등) → 하루 전체 소요, 단독 일정으로 처리

[숙소 복수 입력 처리]
숙소가 2곳 이상일 경우 (예: 1~2일차 A숙소 / 3~4일차 B숙소):
- 각 숙소의 체류 일자에 맞춰 권역 기준점을 전환
- 숙소 변경일 = 이전 숙소 체크아웃 + 신규 숙소 체크인 동시 발생
- 변경일은 이전 숙소 권역에서 신규 숙소 권역으로 이동하는 동선으로 구성
- 짐 이동 고려해 변경일 노드 개수 1개 감산
```

### 5단계 — 하루 동선 뼈대 구성

```
각 일자별로 아래 순서로 뼈대를 먼저 잡는다:

1. 출발지 확정
   - 입국일: 공항
   - 나머지: 숙소

2. 권역 진입 이동 계산
   - 출발지 → 권역 중심부 좌표
   - Google Maps Distance Matrix API로 수단별 소요시간 산출
   - 도보 <15분 → 도보 / 대중교통 <40분 → 대중교통 / 초과 → 택시 병기

3. 권역 내 노드 순서 결정
   - 권역 중심부 기준 도보 이동 가능한 노드 우선 클러스터링
   - 이동 거리 최소화 순서로 정렬 (greedy nearest neighbor)

4. crossZone 발생 조건
   - 노드 개수가 단일 권역으로 채워지지 않을 때
   - 인접 권역으로 확장, 권역 간 이동수단 + 소요시간 삽입

5. 복귀지 확정
   - 출국일: 공항 (출발 2시간 전 도착 고정)
   - 나머지: 숙소
```

### 6단계 — 노드 선정

```
[카테고리 배분]
하루 전체 노드 중:
- 메인 카테고리 노드 → 전체의 50% 이상
- 서브 카테고리 노드 → 1~2개
- 기본 노드 (식사·카페) → 나머지 채움
  └ 맛집필수 선택 시 점심/저녁 시간대 음식·맛집 노드 강제 배치

[스코어링]
각 후보 노드 점수 = 
  (메인 카테 일치 시 × 1.0 | 서브 카테 일치 시 × 0.4) 
  + trendLevel 
  + photogenic 가중치 (사진 중요도 반영)
  + 예산레벨 필터 통과 여부

점수 상위 노드부터 순서대로 채움
같은 카테고리 연속 2개 이상 금지
```

### 7단계 — Fatigue 검증

```
누적 피로도 계산:
이동 30분 = 피로도 1
도보 1시간 = 피로도 1.5
체류 1시간 = 피로도 0.5

체력 높음 → 한계치 10
체력 보통 → 한계치 7
체력 낮음 → 한계치 5

한계치 초과 시 마지막 노드 제거 후 재검증
공항·숙소 이동은 피로도 계산에 포함
```

### 8단계 — 시간 배치

```
각 장소 시작시간 = 이전 장소 종료시간 + 이동시간
종료시간 = 시작시간 + 평균체류시간
영업시간 벗어나면 다음 후보 노드로 교체

공항 도착 / 숙소 체크인·아웃은 고정 시간으로 먼저 배치 후
나머지 노드를 사이에 끼워넣는 방식
```

### 9단계 — 이동 정보 확정

```
구간별 최종 이동 정보 부여:

도보 < 15분      → 도보 (소요시간)
대중교통 < 40분  → 대중교통 (노선명 + 환승횟수 + 요금)
대중교통 > 40분  → 대중교통 + 택시 옵션 병기
공항 구간        → 공항철도 or 리무진버스 (소요시간 + 요금)

출력 형식:
{
  "수단": "도보 | 대중교통 | 택시",
  "소요시간": "N분",
  "노선": "노선명 (대중교통일 경우)",
  "요금": "N엔 (대중교통·택시일 경우)"
}
```

## 제약 조건

```
- 근교(가마쿠라/하코네 등) → 하루 전체 소요, 단독 일정으로 처리
- 맛집필수 → 점심/저녁 시간대 음식·맛집 노드 강제 배치
- 올빼미형 → nightlife 장소 가중치 +20%
- 재방문자 → touristDensity 낮은 장소 우선 (추후 구현)
- 카테고리_메인 = 카테고리_서브 불가 (입력 단계에서 차단)
```
