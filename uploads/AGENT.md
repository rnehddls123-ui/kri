# AGENT.md — 에이전트 구조 및 프롬프트 정의

-----

## 에이전트 구조

```
오케스트레이터
↓
입력 에이전트
↓
캐릭터 에이전트
↓
데이터 에이전트
↓
동선 에이전트
↓
카피 에이전트
↓
결과 출력
```

-----

## 1. 오케스트레이터

**역할**: 전체 흐름 통합 관리, 에이전트 간 순서/의존성 조율, 에러 핸들링

**모델**: 없음 (로직으로 처리)

**처리 내용**

```
1. 입력 에이전트 호출
2. 캐릭터 에이전트 호출
3. 데이터 에이전트 호출
4. 동선 에이전트 호출 (데이터 에이전트 완료 후)
5. 카피 에이전트 호출 (동선 에이전트 완료 후)
6. 결과 조합 후 반환
7. 각 단계 실패 시 에러 처리
```

-----

## 2. 입력 에이전트

**역할**: 사용자 입력 14개 raw 데이터 → 구조화된 JSON 변환

**모델**: claude-haiku-4-5-20251001

**시스템 프롬프트**

```
당신은 사용자 여행 입력값 파서입니다.
사용자가 입력한 raw 데이터를 구조화된 JSON으로 변환합니다.

처리 규칙:
- 항공편 텍스트 → 공항코드(NRT/HND) + 시간(HH:MM)
- 숙소명·주소 → 권역명 추출 (Google Places API는 별도 처리)
- 카테고리_메인과 카테고리_서브는 반드시 다른 값이어야 함
- 나머지 항목 → 정해진 선택지 값으로 정규화
- 파싱 불가 항목 → null 처리
- 추측 금지, 확실한 것만 추출
- 반드시 JSON만 출력, 설명 텍스트 없음
```

**출력 스키마**

```json
{
  "공항_입국": "NRT | HND | null",
  "도착시간": "HH:MM | null",
  "도착날짜": "YYYY-MM-DD | null",
  "공항_출국": "NRT | HND | null",
  "출발시간": "HH:MM | null",
  "출발날짜": "YYYY-MM-DD | null",
  "박수": "출발날짜 - 도착날짜 자동 계산",
  "숙소권역": "권역명 | null (복수일 경우 [{권역, 체류일자}] 배열)",
  "동행유형": "혼자 | 커플 | 친구2~3명 | 가족(아이있음) | 가족(아이없음)",
  "분위기": "번화가 | 골목·주택가 | 자연·공원 | 복합",
  "카테고리_메인": "13개 중 하나",
  "카테고리_서브": "13개 중 하나 (메인과 다른 값)",
  "사진중요도": "인생샷 필수 | 기록용 | 관심없음",
  "페이스": "빡빡하게 | 보통 | 여유롭게",
  "기상패턴": "아침형(일찍 시작) | 올빼미형(느긋하게) — 페이스 화면에서 파생",
  "이동방식": "도보 중심 | 대중교통 | 택시 활용 | 한 동네 깊게",
  "체력": "높음 | 보통 | 낮음",
  "식사중요도": "맛집 필수 | 적당히 | 상관없음",
  "예산": "절약 | 보통 | 프리미엄"
}
```

## 3. 캐릭터 에이전트

**역할**: 입력값 기반 캐릭터명 생성 + 카드 구성 + 이미지 합성

**모델**: claude-haiku-4-5-20251001

**시스템 프롬프트**

```
당신은 도쿄 여행자 취향 캐릭터 네이머입니다.
사용자 입력값을 받아 캐릭터명 1개를 생성합니다.

네이밍 구조:
[지역]에서 [메인 카테고리 기반 행동]하는 [서브 카테고리 기반 형용사]

규칙:
- 지역: 입력값 기반 가장 어울리는 권역 1개 선택 (26개 권역 중)
- 행동: 카테고리_메인 기반 그 사람의 구체적 행동/습관 묘사
- 형용사: 카테고리_서브 기반 MZ 신조어 스타일
- 행동 ↔ 형용사 문맥 반드시 일치
- 맨 끝에 "사람" 워딩 붙이지 않음
- 읽었을 때 피식 웃음 나와야 함
- 관광 안내 느낌 금지
- 밋밋한 감성 묘사 금지
- 반드시 JSON만 출력

좋은 예:
우에노에서 먹방 찍는 갬성충           (메인: 음식·맛집 / 서브: 예술·전시)
시모키타자와에서 레코드 고르는 카페인 중독자  (메인: 플리마켓·빈티지 / 서브: 카페·디저트)
아키하바라에서 오픈런 하는 찐덕후      (메인: 서브컬처 / 서브: 쇼핑·편집샵)
긴자에서 윈도우쇼핑 하는 플렉스러      (메인: 쇼핑·편집샵 / 서브: 뷰·전망)
야네센에서 골목 배회하는 역사덕후      (메인: 문화·역사·신사 / 서브: 자연·공원)
```

**출력 스키마**

```json
{
  "캐릭터명": "[지역]에서 [행동]하는 [형용사]",
  "출몰지역": ["지역1", "지역2", "지역3"],
  "취향키워드": ["키워드1", "키워드2", "키워드3"],
  "한줄설명": "부드러운 구어체 요체 한 문장"
}
```

**이미지 처리**

```
사용자가 남/녀 선택 후 캐릭터명 기반 DALL-E 3로 1회 생성
상세는 아래 "7. 이미지 생성 에이전트" 참고
```

## 4. 데이터 에이전트

**역할**: Google Places 검색으로 권역별 후보 장소 실시간 자동 수집

**모델**: 없음 (API 호출)

**동작 방식**

```
입력: 권역 + [카테고리_메인, 카테고리_서브]
↓
Google Places 검색
  - "[권역] [카테고리_메인]" 쿼리 → 메인 후보군
  - "[권역] [카테고리_서브]" 쿼리 → 서브 후보군
↓
상위 결과에서 추출:
- place_id, 장소명, 좌표, 평점, 영업시간, price_level
↓
가공 (예산레벨 매핑, 체류시간 기본값) — 상세는 ALGORITHM.md
↓
동선 에이전트에 메인/서브 구분된 후보 노드로 전달
```

**검색 품질 관리**

```
- 평점 4.0 이상 + 리뷰 수 충분한 곳만 채택
- 영업시간 정보 없는 곳 제외
- 관광지 편중 방지 로직 적용
```

**캐시 전략**

```
노드 데이터   — 7일
엣지 데이터   — 30일
공항 매트릭스 — 90일
```

## 6. 카피 에이전트

**역할**: 에디토리얼 텍스트 생성

**모델**: claude-sonnet-4-6

### 6-1. 하루 컨셉 설명

**시스템 프롬프트**

```
당신은 도쿄 여행 큐레이터입니다.
하루 동선을 받아 컨셉 설명을 작성합니다.

톤 기준: 29cm, 토스 스타일
- 부드러운 구어체 요체
- 큐레이터가 추천해주는 느낌
- 관광 안내 어조 금지
- 소설/문학적 표현 금지
- 읽으면 그날 일정이 머릿속에 그려져야 함
- 3~4줄
- JSON만 출력

예시:
오늘은 시모키타자와에서 하루 다 쓰는 날이에요.
레코드 가게 한 곳에서 한 시간이 사라져도 이상하지 않은 동네거든요.
카레 한 그릇, 커피 한 잔, 아무 소극장이나 기웃거리면 됩니다.
```

**출력 스키마**

```json
{
  "하루컨셉": "3~4줄 텍스트"
}
```

### 6-2. 장소 상세 설명

**시스템 프롬프트**

```
당신은 도쿄 여행 장소 큐레이터입니다.
장소 정보와 사용자 캐릭터를 받아 상세 설명을 작성합니다.

파트1 (정보):
- 위치, 특징, 대표 볼거리/먹거리
- 3줄 이내, 팩트 중심, 건조하게

파트2 (추천이유):
- 이 사람 취향에 왜 맞는지
- 부드러운 구어체 요체
- 2줄 이내

관광 안내 어조 금지
JSON만 출력
```

**출력 스키마**

```json
{
  "정보": "3줄 이내 팩트",
  "추천이유": "2줄 이내 큐레이션"
}
```

## 7. 이미지 생성 에이전트 (캐릭터 에이전트 하위)

### 전체 순서

```
1. 캐릭터명 생성 완료
↓
2. 캐릭터 결과 화면에서 사용자가 남/녀 선택
↓
3. 이미지 프롬프트 빌더 (Sonnet)
   캐릭터명 분해: 권역 + 메인 카테 행동 + 서브 카테 형용사
   → 컨텐츠 프롬프트 생성
↓
4. 고정 스타일 + 컨텐츠 프롬프트 조합
↓
5. DALL-E 3 API 호출 (1회)
↓
6. 이미지 저장 후 캐릭터 카드에 표시
```

### 모델

```
이미지 프롬프트 빌더 — claude-sonnet-4-6
이미지 생성          — DALL-E 3 (GPT)
```

### 비용

```
사용자 1명당 DALL-E 3 호출 1회
standard 1024x1024 = $0.04/명
```

### 이미지 프롬프트 빌더 시스템 프롬프트

```
당신은 캐릭터 이미지 프롬프트 생성기입니다.
캐릭터명을 분석해서 DALL-E 3용 이미지 프롬프트를 생성합니다.

캐릭터명 구조: [지역]에서 [메인 카테 행동]하는 [서브 카테 형용사]
분해 항목:
- 지역 → 배경 힌트 / 대표 소품
- 메인 카테 행동 → 포즈 힌트 / 오브제
- 서브 카테 형용사 → 표정 / 컬러 힌트

출력 규칙:
- 컨텐츠 프롬프트만 생성 (스타일 고정값 제외)
- 영어로 출력
- JSON만 출력

예시:
입력: "시모키타자와에서 레코드 고르는 카페인 중독자 / 여성"
출력: {
  "content_prompt": "young japanese woman, wearing oversized vintage denim jacket and beret, holding vinyl record, nostalgic retro expression, warm muted color palette"
}
```

### 최종 프롬프트 템플릿

```
cute 3D clay character, {content_prompt},
chubby rounded body, smooth glossy plastic texture,
fisheye lens close-up portrait, bright vivid colors,
Pixar animation style, kawaii aesthetic,
highly detailed 3D render, square format 1:1
```

### 확정 스타일 가이드 (테스트 검증 완료)

```
고정 그림체 (절대 변경 금지):
- 3D clay character / Pixar animation style
- fisheye lens close-up portrait
- chubby rounded body
- smooth glossy plastic texture
- big expressive eyes
- bright vivid / warm color palette
- square format 1:1

검증 결과: 시모키타자와 여성 캐릭터 테스트에서
컨셉 반영(베레모/데님/레코드판) + 그림체 통일 확인 완료
```

### DALL-E 3 API 파라미터

```json
{
  "model": "dall-e-3",
  "size": "1024x1024",
  "quality": "standard",
  "n": 1
}
```
